A Secret stores the same key/value shape as a ConfigMap, but the API shows values
as base64. Base64 is **encoding, not encryption**: anyone allowed to `get
secrets` in the namespace can read the clear value. Encryption at rest only
happens if the cluster is configured for it.

A5 creates `web-basic-auth` from an `.htpasswd` file generated by
`scripts/mkpasswd.sh`. The file is mounted as `/etc/nginx/auth/.htpasswd`, and
nginx answers 401 without credentials and 200 for `lab:labpass`. The Secret is
typed `Opaque` and uses `stringData`, so the manifest holds a readable demo hash
rather than base64.

The manifest sets `defaultMode: 0644` for the mounted file because nginx worker
processes run as a non-root user and must be able to read it. A stricter mode is
possible, but then the file ownership has to match the reading user.

A7 shows the other pattern: the PostgreSQL password lives in
`postgres-credentials` and reaches the container with `envFrom.secretRef`, so the
password is not written in the pod template. Environment variables are easier to
leak than mounted files, because every child process inherits them.
